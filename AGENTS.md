# Portfolio rules

## Never publish
- Phone numbers, home addresses, or personal email addresses, including school email.
- Grades, salary, visa status, date of birth, secrets, credentials, or tokens.
- Anything in private/. Keep private/ in .gitignore before adding private files.
- The original source folder ezchen-portfolio-main/ or unrelated local files in the class website repository.

## Ask me first
- Before any git push, public deployment, repository creation, or other change on GitHub.
- Before deleting or overwriting an existing file. Describe the proposed changes first.

## Style and content
- Use plain HTML and CSS; keep the design clean, minimal, professional, and casual.
- Use purple and grey with complementary neutral colors and streamlined navigation.
- Present projects as a gallery with links to each project.
- Use the existing portfolio as the factual source; do not invent achievements or personal details.
- Preserve source section order: About, History (Experience and Education), Projects, Contact.
- Make the page responsive and accessible, with visible keyboard focus and descriptive image text.
- Keep asset paths relative so the site can run under a GitHub Pages repository path.

## When you finish
- Explain what changed, what was skipped, and verification limits.
- List every newly created file.
- Show the local page before proceeding with publication.
- Before publication, reread this file, list the exact files to push, and wait for explicit approval.
